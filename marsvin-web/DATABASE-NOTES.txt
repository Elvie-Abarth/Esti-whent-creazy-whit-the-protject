MARSVIN DATABASE - NOTES
=========================

WHAT IT IS
----------
This project uses SQL Server LocalDB (a lightweight SQL Server instance
that runs under your Windows user account) as its database. It is NOT a
file inside this project folder - it's managed by SQL Server itself.

Database name:  MarsvinDb
Server name:    (localdb)\MSSQLLocalDB
Connection string: see appsettings.json -> ConnectionStrings:MarsvinDb

WHERE THE FILES ACTUALLY LIVE
------------------------------
C:\Users\estib\MarsvinDb.mdf       (the data)
C:\Users\estib\MarsvinDb_log.ldf   (the transaction log)

The schema script (Data\Sql\schema.sql) and the connection string
(appsettings.json) ARE part of this project - those are the source of
truth. The .mdf/.ldf files are just the running database's storage and
get recreated automatically if they ever go missing (see below).

HOW TO OPEN / BROWSE THE DATABASE
----------------------------------
Using SQL Server Management Studio (SSMS):
  1. Open SSMS.
  2. Connect to server: (localdb)\MSSQLLocalDB
  3. Authentication: Windows Authentication
  4. Expand Databases -> MarsvinDb -> Tables to see Products, Animals,
     StockProducts, Users, PendingLogins, CartItems, Orders, OrderItems,
     Promotions, Shifts, TimeOffRequests.
     Right-click a table -> "Select Top 1000 Rows" to view its data.

From the command line:
  sqlcmd -S "(localdb)\MSSQLLocalDB" -d MarsvinDb

DEMO LOGIN CREDENTIALS
------------------------
Seeded automatically the first time the database is created (see
DbInitializer.SeedAccountsIfEmpty). Demo-only - not fit for anything else:

  Admin:    admin@marsvin.dk     / Admin123!
  Employee: employee@marsvin.dk  / Employee123!
  Employee: employee2@marsvin.dk / Employee123!
  Employee: employee3@marsvin.dk / Employee123!
  Employee: employee4@marsvin.dk / Employee123!

Customers always register themselves at /Account/Register - there is no
seeded customer account. Admins can create additional Employee/Admin
accounts from /Admin/Users.

HOW TO START THE PROJECT
--------------------------
From the marsvin-web folder:
  dotnet run

On startup, the app automatically:
  1. Creates the MarsvinDb database if it doesn't exist yet.
  2. Runs schema.sql. Every table is created once, the first time it's
     missing, and left alone after that - nothing is ever dropped.
  3. Seeds Products/Animals/StockProducts from Data\DemoCatalog.cs, and
     seeds the Admin/Employee accounts above - but only on a database
     that doesn't have that data yet (checked by row count).

You do NOT need to manually create the database or run any SQL scripts
yourself - just running the project handles it.

NOTE: earlier versions of this project dropped and recreated the catalog
tables on every startup. That stopped being safe once admin/employee
pages could edit the catalog live - it would have erased their changes
on every restart. Every table is now create-once. If you want a fully
fresh database, delete it yourself (see below) and let the app recreate
and reseed it.

IF THE DATABASE WON'T CONNECT / SEEMS DISCONNECTED
-----------------------------------------------------
LocalDB is not a background service that's always running - it starts
on demand. Try these in order:

1. Check its status:
     sqllocaldb info MSSQLLocalDB

2. Just start it (usually all that's needed):
     sqllocaldb start MSSQLLocalDB

3. If the instance itself is corrupted (info/start commands give odd
   errors like "Cannot create an automatic instance" or "Unexpected
   error occurred inside a LocalDB instance API method call"), reset
   the LocalDB ENGINE (this does not touch your data files):
     sqllocaldb stop MSSQLLocalDB
     sqllocaldb delete MSSQLLocalDB
     sqllocaldb create MSSQLLocalDB
     sqllocaldb start MSSQLLocalDB

4. If the MarsvinDb database itself is missing or broken, no manual
   recovery is needed - just run the project again:
     dotnet run
   DbInitializer.cs recreates the schema and reseeds the demo data
   automatically every time it starts.

So in short: as long as appsettings.json still points at
(localdb)\MSSQLLocalDB, simply running the project again will self-heal
the database if it's missing. The only thing that ever needs manual
fixing is the LocalDB instance itself (step 3 above).

HOW TO RESET TO A FRESH DATABASE
-----------------------------------
Since tables are no longer dropped automatically, resetting is a manual
step now (this deletes everything - accounts, orders, admin edits):

  sqlcmd -S "(localdb)\MSSQLLocalDB" -Q "ALTER DATABASE MarsvinDb SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE MarsvinDb;"

Then just run the project again - it recreates and reseeds everything.

RELEVANT FILES IN THIS PROJECT
---------------------------------
See DATABASE-ARCHITECTURE.md and WEBSITE-ARCHITECTURE.md for the full
picture (schema design, request pipeline, auth flow, site map, testing
strategy) - this is just the quick pointer list:

Data\Sql\schema.sql          - table definitions (Products/Animals/StockProducts,
                               Users/PendingLogins/CartItems/Orders/OrderItems/
                               Promotions/Shifts/TimeOffRequests)
Data\DbInitializer.cs        - creates the DB, runs the schema, seeds demo data + accounts
Data\SqlCatalog.cs           - reads AND writes the product/animal catalog (ICatalog + ICatalogAdmin)
Data\SqlUserAccountStore.cs  - user accounts (used by /Account and /Admin/Users)
Data\SqlPendingLoginStore.cs - single-use email login-confirmation tokens
Data\SqlCartStore.cs         - shopping cart
Data\SqlOrderStore.cs        - checkout: validates availability, decrements stock, records the order
Data\SqlPromotionStore.cs    - promotions (Admin/Promotions)
Data\SqlShiftStore.cs        - staff work schedule (Admin/Schedule)
Data\SqlTimeOffRequestStore.cs - employee day-off requests (Account/Profile, Admin/Schedule)
Data\SmtpEmailSender.cs      - real SMTP email (login confirmation, inactivity warnings, notifications)
Data\DemoCatalog.cs          - the in-memory demo data used to seed the database
appsettings.json             - connection string (ConnectionStrings:MarsvinDb), SMTP host/port
Program.cs                   - cookie authentication + authorization setup, DI wiring
